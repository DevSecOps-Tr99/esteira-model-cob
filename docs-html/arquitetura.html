Arquitetura

Princípio orientador

O JCL não muda. A troca é na camada de orquestração e governança — de Jira/HexaVision/ChangeMan para GitHub/GitHub Actions/Python — preservando a lógica atual, os JCLs e o Control-M.

Por que o motor fica em Python, não no YAML do workflow

O GitHub Actions controla quando a execução começa, qual runner é usado, quais aprovações são necessárias e o status do Pull Request. O motor Python controla toda a lógica: parsing, regras, dependências, score, simulação, submissão e evidências. Isso evita acoplamento ao GitHub Actions — a mesma esteira poderia rodar sob Azure DevOps, Jenkins ou como CLI local, trocando apenas a camada de disparo.

Fases do projeto

  • Fase 1 (este repositório) — novo SCM e nova esteira. Retira Jira e HexaVision da criação/versionamento; preserva os JCLs; convive com as validações do HexaVision ainda não substituídas.
  • Fase 2 — substituição das validações do HexaVision, após inventário e classificação completa das regras (técnica, processo, segurança, negócio, regulatória) — ver kickoff-perguntas.md.

Gaps conhecidos vs. uma esteira real de migração do Endevor

O mapeamento acima descreve a intenção arquitetural. Comparado a uma esteira real de migração do Endevor já em operação no banco (COBOL/Assembler/mapas/ Control-M/JCL, ferramental DBB + Wazi Deploy + JFrog), faltam hoje: um estágio de build/empacotamento, a gravação do fonte na biblioteca-alvo (distinta da submissão do job) e o tratamento de componentes com caracteres hexadecimais não roundtrippable (que só podem trafegar como binário). Ver reuniao-endevor-jcl-binarios.md para o paralelo completo, a lista de diferenças e o plano de ação.

Ambiente de validação

O GitHub Actions hospedado pela GitHub roda o pytest e o wrapper do ProLeap (via actions/setup-java), mas não alcança rede interna. Para provar a esteira rodando "dentro da rede do banco" — o nó "Self-hosted Runner" deste diagrama — e para validar manualmente tudo o que uma máquina de desenvolvimento corporativa às vezes não permite instalar (JDK, Maven, gh CLI), ver ambiente-validacao.md.
